# Prompts given to the agents

All agents ran as `sonnet`. `SCRATCH` stands for the session scratchpad directory; `TEAM` is the project created by `autocraft init . --tool claude-code --team starter --archetype script-automation`, with the spec copied to `docs/specs/receipt-tally.md`.

## Solo, pass 1
> You are the ONLY engineer on this job: you do the design, the code, the tests, your own review and the final "is it ready?" check, all yourself. Nobody else will look at the work before it goes to the owner.
> Spec (read it fully): SCRATCH/solo/SPEC.md. Build everything in the directory SCRATCH/solo/work (create it; run `git init` there and commit when done).
> Deliver tasks T1 and T2 of the spec: the `receipt_tally` Python package (stdlib only, runnable as `python -m receipt_tally` from the project root), a test suite in `tests/` (pytest is installed; Python 3.13), a small `examples/` folder with two fake CSVs (one per bank layout) and a sample config, and a plain-language README.md for the owner (how to run monthly, how to write rules, what the errors mean; at most 60 lines). Every acceptance criterion should be covered by a test.
> Rules: work only inside that directory; do not read or search anywhere else on this machine (in particular nothing under /home/user/autocraft); do not use the network or push anything. When you consider the project ready to hand to the owner, stop and reply in at most 10 lines: what you built, test count and result, and anything you are unsure about.

## Solo, pass 2 (self-review control; same agent, same context)
> Second pass, same rules as before (same directory, nothing else on the machine, no network). Now review your own finished work critically as if you were a strict outside reviewer: run the real program (`python -m receipt_tally`) against hostile and sloppy inputs (bad or odd configs, odd amounts and dates, huge or malformed numbers, control characters, odd --month/--out values, odd file encodings), check each acceptance criterion by running it, and look for anything that can crash with a traceback, print wrong money, or leak. Fix every problem you find, each with a test that fails before the fix and passes after, keep the package at or below 400 lines, run the full suite, and commit. Reply in at most 8 lines: what you found and fixed, and the test count.

Note: this prompt names categories that overlap with the outside check. See the README caveats.
